# БЕРТА — сайт для развёртывания

Next.js 15, React 19, Payload CMS 3, SQLite. Репозиторий содержит исходники действующей версии сайта, необходимые изображения и документы, а также начальное публичное наполнение CMS. Нужен VPS с Docker Compose либо платформа с поддержкой Dockerfile и постоянного диска. Обычный статический хостинг не подходит.

## Запуск на сервере

1. Клонируйте приватный репозиторий с доступом только на чтение:

   ```sh
   git clone https://git.kiboai.ru/myxa/berta-site.git
   cd berta-site
   cp .env.example .env
   chmod 600 .env
   ```

2. В `.env` укажите:
   - `NEXT_PUBLIC_SITE_URL` — полный адрес сайта, например `https://okna-berta.ru`, без завершающего `/`. Он используется при сборке и запуске; смена домена требует пересборки.
   - `PAYLOAD_SECRET` — постоянный случайный секрет от 32 символов.
   - `CMS_ADMIN_EMAIL` и `CMS_ADMIN_PASSWORD` — первый администратор и уникальный пароль от 16 символов. Создаются только при первом запуске пустой базы.
   - При занятом порте задайте `BERTA_HTTP_PORT`, например `3100`.

   Два независимых секрета можно получить двумя запусками `openssl rand -hex 32`. Не добавляйте заполненный `.env` в Git.

3. Соберите и запустите:

   ```sh
   docker compose up -d --build
   docker compose ps
   docker compose logs --tail=100 web
   curl -I http://127.0.0.1:3000/
   ```

   Первый запрос создаёт структуру базы, импортирует публичное наполнение и изображения. Это может занять несколько минут. При другом `BERTA_HTTP_PORT` измените порт проверки.

4. Направьте DNS домена на целевой сервер и настройте HTTPS в установленном обратном прокси. Пример отдельного сайта Caddy, если этот домен ещё не обслуживается другим приложением:

   ```caddyfile
   okna-berta.ru {
       reverse_proxy 127.0.0.1:3000
   }
   ```

5. Проверьте страницы, скачивание документов, форму заявки и вход по адресу `/admin`. Заявки сохраняются в CMS. CRM изначально выключена: её подключение и реальная доставка требуют отдельной настройки и проверки.

## Постоянные данные и обновления

Docker volume `berta-storage` хранит базу и загруженные медиа в `/app/storage`. Сохраняйте весь volume и `.env` в защищённой резервной копии перед обновлениями. Не используйте `docker compose down -v`: это удалит данные. `PAYLOAD_SECRET` нужно сохранять между развёртываниями.

Обновление: `git pull --ff-only`, затем `docker compose up -d --build`. Начальное наполнение импортируется один раз; последующие изменения редактора сохраняются. После первой успешной инициализации пароль администратора можно убрать из `.env`; он не служит механизмом смены пароля существующей учётной записи.

В Coolify или аналогичной платформе: ветка `main`, Dockerfile в корне, внутренний порт `3000`, постоянный диск `/app/storage`, переменные из `.env.example`, `NEXT_PUBLIC_SITE_URL` также как аргумент сборки. Проверка здоровья использует HTTP на `127.0.0.1:3000`; настраивайте доступ к приватному Git отдельным ключом только на чтение. SSH-ссылка Forgejo с портом 2222 требует доступного маршрута до сервера; для внешнего хостинга используйте HTTPS или отдельно настроенный SSH-доступ.

## Что переносится

- Публичное содержание сайта, 4 алюминиевые системы, 8 решений, 9 дополнительных продуктов, офисы, поставщики, документы и изображения.
- Админка Payload, формы, миграции базы, sitemap и robots.
- Утверждённые характеристики и иллюстрации AS 63 и F 50 из действующей версии.

Не включены исходная база, заявки, пользователи, пароли, CRM-ключи, история редакций, демонстрационные проекты, отчёты, рабочие DOCX/XLSX, зависимости и готовые сборки. Для переноса существующих заявок и учётных записей нужен отдельный защищённый перенос базы и медиа. Git не является резервной копией пользовательских данных.

Этот репозиторий фиксирует текущую версию сайта. Дополнительные SEO-страницы из семантического ядра и полный план SEO-проверки остаются отдельной задачей. Индексация Google/Yandex разрешена для `okna-berta.ru` и `www.okna-berta.ru`; при другом основном домене нужно также изменить правила в `src/app/robots.ts` и `src/lib/metadata.ts`.

## Локальная разработка

Node.js 22, pnpm 11.9.0. Установите зависимости через `pnpm install --frozen-lockfile`. В локальном `.env` задайте `DATABASE_URL=file:./storage/berta.db`, `CMS_MEDIA_DIR=./storage/media`, `NEXT_PUBLIC_SITE_URL=http://localhost:3000` и свои начальные секреты. Создайте `storage/media`, примените `BERTA_BUILD=1 pnpm cms:migrate`, запустите `pnpm dev`. Команда `pnpm build` проверяет production-сборку; Docker запускает самостоятельную сборку Next.js. Отправка почты и восстановление пароля по email требуют отдельного почтового адаптера.
